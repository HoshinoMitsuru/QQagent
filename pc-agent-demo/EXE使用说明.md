# QQAgent 控制台 · 使用说明

> 面向：把它丢到一台 Windows 虚拟机上、希望「双击就能用」的人。
> 目标：**你只需要预先打开 QQ 并登录**，其余全部在界面里点。

---

## 0. 一页速览

```
1. 把 qq-agent.exe 拷到虚拟机上任意**可写**目录（例如 D:\QQAgent\）
2. 双击它 → 弹 UAC → 点「是」
3. 浏览器自动打开控制台（托盘里会出现图标）
4. 按界面上的顺序点：① 定位 QQ → ② 启动 QQ → ③ 体检 → ④ 填 API Key → ⑤ 开始常驻
```

需要你做的只有两件事：**把 QQ 打开并登录**、**在界面里填一次 API Key**。
其余（找 QQ、带正确参数重启、等待就绪、启动常驻、看日志）都在界面里。

---

## 1. 为什么是「一个 exe + 一个网页」

原来这套东西要你开终端敲一串命令：

```powershell
cd D:\Psyche\Sealdice-AIChat\pc-agent-demo
$env:Path = "...\venv\Scripts;$env:Path"
python -X utf8 agent.py --peek 10
python -X utf8 agent.py --input-test
python -X utf8 agent.py --send "测试"
python -X utf8 agent.py
```

现在这些命令**没有消失，而是变成了界面上的按钮**。这一点是刻意的：命令行还在、
还能用、还是同一份代码（见 §6），出问题时你可以照旧手工跑一遍对比。
界面只是把「顺序 + 参数 + 校验」固化了，不替你做决定。

## 2. 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| 系统 | Windows 10 / 11（64 位） | 依赖 UIAutomation，仅 Windows |
| 权限 | 管理员 | 自启注册、VM 加固、结束 QQ 进程需要它 |
| QQ | QQNT（新版 Electron 版） | 老版 QQ 的控件结构不同，本项目未适配 |
| 网络 | 能访问你的模型接口 | 内置默认是 DeepSeek 官方地址 |
| 依赖 | **不需要装 Python** | 解释器和全部库都打进了 exe |

> **不要放到 `C:\Program Files`**。那里不可写，程序会退而把数据放到
> `%LOCALAPPDATA%\QQAgent\`。想便携使用（整个目录拷来拷去），就放可写目录。

## 3. 界面上的五个步骤

### ① 定位 QQ 程序

点「重新查找」。查找顺序：手动指定 → 注册表 → 常见安装目录 → 各盘根目录。

> 本机的 QQ 在 `D:\QQ.exe` —— **盘根、非标准路径**，前三种都找不到，靠第四种兜住。
> 如果你的 QQ 更奇怪，在「运行环境」里直接填完整路径。

### ② 启动 QQ

「启动 QQ」只在 QQ **完全没在跑**的时候可用。它会带上
`--force-renderer-accessibility` 参数启动 —— **没有这个参数，UIA 树是空壳，
读不到任何消息**。

> 登录必须你自己来。程序不碰登录、不碰验证码、不碰任何账号凭据。

### ③ 界面可读（无障碍树体检）

点「体检」。这一步判断的是「agent 到底能不能看见 QQ 的界面」，判据是
**能不能读到会话列表和消息列表**，而不是去猜命令行参数。

> 为什么不看命令行：启动参数**只在 QQ 主进程首次启动时生效**。QQ 已经在跑的时候
> 再执行一次带参数的命令，它只会把已有窗口唤到前台，参数根本不应用。
> 查命令行会告诉你「参数都在」，而实际什么都读不到 —— 我们只认读得到东西。

**如果体检失败**，点「重启 QQ 到可读状态」。它会完全退出 QQ（含托盘进程）再带参数拉起。
登录态保留、一般不用重新扫码，但**正在输入的文字会丢** —— 所以这个按钮有二次确认。

### ④ 填参数

「参数配置」共 6 组：

| 分组 | 你至少要动的地方 |
|---|---|
| **模型接入** | **API Key（必填）**；接口地址、模型名按需改 |
| 对话行为 | 是否回群聊、非文本消息怎么处理、回复字数上限 |
| 节奏与聚合 | 对方连发消息时合并成一次调用 |
| 风控与排队 | 每分钟最多回几条 —— **决定能同时服务几个会话** |
| 多会话发现 | 扫会话列表找新消息，这是多会话能力的核心开关 |
| 前台与稳定性 | 用完是否归还前台、消息方向判定、OCR 兜底 |

下面还有一组「运行环境」：QQ 路径、监听地址与端口、CDP 开关、开机自动启动等。

> **API Key 只写进 `secrets.local.json`，不会写进 `config.json`。**
> 后者是「可以公开」的那个文件，前者已被 `.gitignore` 排除。
> 界面回显的 Key 永远是掩码，接口也不会把明文吐回来（有测试守着这条）。

### ⑤ 开始常驻

**建议先点「只读运行（不发送）」观察几分钟**：日志里能看到它读到了谁的消息、
方向对不对、昵称对不对，但一条都不会发出去。确认无误后再切到会真的发送的常驻。

停止用「停止常驻」。它不会硬杀进程：先放一个停止哨兵文件，给主循环最多 12 秒
**把队列里已经生成好的回复发完**，再退出。这一步不能省 —— 丢了就是
「对方明明发了消息，我们却永远不回」。

## 4. 从只读到真发：验证顺序

界面的「验证与试运行」里，建议按这个顺序走。会碰 QQ 的任务必须串行执行，
常驻运行时它们会被自动禁用（避免两个进程抢同一个输入框）。

| 顺序 | 按钮 | 会不会发消息 | 期望看到什么 |
|---|---|---|---|
| 1 | 自检 | 否 | 密钥 OK、模型几百毫秒返回 |
| 2 | 只读诊断 | 否 | `群聊=False`、`【我方】/【对方】`与界面左右一致 |
| 3 | 会话列表体检 | 否 | 能看到 agent 眼里的会话列表与未读徽标 |
| 4 | 输入框写入测试 | **否** | 写入生效 → 回读一致 → 清空成功 |
| 5 | 彩排：完整读一轮 | 否 | 读消息 → 生成回复 → 三重身份复核 |
| 6 | 彩排：写到输入框为止 | **否** | 和常驻同一条链路，只在最后一击前收手 |
| 7 | **真发一条** | **是** | QQ 里真的出现这条消息 |

第 4 步失败通常意味着中文进不了输入框（剪贴板链路问题）；
第 5、6 步失败通常意味着身份复核没过 —— 那说明**检测机制在正常工作**，
日志里会写明是标题对不上还是 QQ 号对不上。

## 5. 虚拟机路线：这台机器的加固

你选择 VM 路线是为了彻底绕开两件事：**抢你屏幕**和**锁屏不可用**。界面上的
「虚拟机加固与无人值守」就是为此准备的。

### 5.1 禁用自动锁屏

一键执行这些改动（全部可逆，都能在「电源和睡眠」里手动改回）：

| 项 | 改什么 |
|---|---|
| 显示器自动关闭 | `powercfg /change monitor-timeout-ac 0` |
| 硬盘自动关闭 | `powercfg /change disk-timeout-ac 0` |
| 系统自动睡眠 | `powercfg /change standby-timeout-ac 0` |
| 系统自动休眠 | `powercfg /change hibernate-timeout-ac 0` |
| 电池下显示器/睡眠 | 同上，`-dc` 版本 |
| 屏保 | 注册表 `ScreenSaveActive=0` |
| 锁屏界面 | 组策略 `NoLockScreen=1`（**仅专业版生效**，家庭版会失败但不影响其它项） |

> 为什么非做不可：**桌面锁屏时，UIA 的读取还能工作，但点击、按键、Invoke 会全部失败。**
> 表现是日志里不断重复「发现 → 入队 → 复核失败 → 重排」，看起来像程序坏了。
>
> ⚠️ 宿主机锁屏**不影响** guest（虚拟机照常运行），但**宿主机睡眠/休眠会挂起虚拟机**。

### 5.2 开机自动启动

注册一个登录计划任务，带「最高权限」标记。用计划任务而不是启动文件夹，
是因为**以最高权限运行的登录任务不会弹 UAC** —— 无人值守的虚拟机上这是决定性的。

### 5.3 建议的部署方式

```
虚拟机（Windows，常开）
├─ qq-agent.exe          管理员启动，托盘常驻
├─ QQ（带无障碍参数）      你手动登录一次，之后一直是登录态
└─ 控制台网页             从宿主机浏览器也能开（见 §7）

宿主机
└─ 完全不参与，也就完全不受打扰
```

## 6. 命令行还留着（出问题时的退路）

同一个 exe 就是 agent 本体，把参数透传进去即可 —— **界面里跑的和命令行里跑的是同一份代码**：

```powershell
qq-agent.exe --run-agent --selftest
qq-agent.exe --run-agent --peek 10
qq-agent.exe --run-agent --input-test
qq-agent.exe --run-agent --send "测试"
qq-agent.exe --run-agent                  # 常驻（不开界面）
qq-agent.exe --run-qqid  --enroll-all     # 给所有会话取号
qq-agent.exe --version
qq-agent.exe --help
```

其它开关：

| 开关 | 作用 |
|---|---|
| `--safe` | 安全启动：不自动拉起 QQ、不建托盘、不开浏览器。只起 HTTP 服务 |
| `--run-agent X` | 以 agent.py 的身份运行 X（内部使用） |
| `--run-qqid X` | 以 qqid.py 的身份运行 X（内部使用） |

## 7. 从别的设备打开界面

控制台默认只监听 `127.0.0.1`（只有本机能开）。想在宿主机浏览器里操作虚拟机里的控制台：

1. 界面里「运行环境 → WebUI 监听地址」改成 `0.0.0.0`，保存，重启程序
2. 程序启动时会在日志里打印形如 `http://192.168.x.x:8765/?t=<令牌>` 的地址
3. 用那个地址从宿主机打开

> **安全边界**：这个界面能读你的聊天记录、能冒充你发消息、还能结束你的 QQ 进程。
> 所以每次启动都会生成一个随机令牌，**首屏 HTML 也必须带令牌才能打开** ——
> 不知道令牌的人连页面都拿不到。即便如此，也请只在可信内网（NAT 后的虚拟机网络）里用，
> **绝对不要**把端口映射到公网。
>
> 令牌在启动日志里，也在托盘菜单「打开控制台界面」直接打开的地址里。

## 8. 排错对照表

**先看这一条**：程序里所有失败都会带一个错误码（形如 `E-QQ-004`）。
界面上的码**可以点** —— 点一下会弹出这个码的「可能原因 + 怎么办」。
如果懒得点，直接按下面的表查：

| 错误码 | 一句话 | 先做什么 |
|---|---|---|
| `E-ENV-001` | 数据目录不可写 | 把 exe 移到 `D:\QQAgent\` 这类可写目录 |
| `E-ENV-003` | 没有管理员权限 | 右上角「提权重启」 |
| `E-ENV-005` | 端口被占用 | 「运行环境」里换个端口 |
| `E-ENV-006` | 桌面已锁屏 | 解锁；或点「执行加固」禁用自动锁屏 |
| `E-QQ-001` | 找不到 QQ.exe | 「运行环境」里手填完整路径 |
| `E-QQ-002` | QQ 没在运行 | 点「启动 QQ」 |
| `E-QQ-003` | 找不到可见的 QQ 主窗口 | 把 QQ 从托盘点出来（**不用重启**） |
| `E-QQ-004` | 无障碍树是空壳 | 点「重启 QQ 到可读状态」（**必须完全退出后带参重启**） |
| `E-QQ-005` | 重启 QQ 失败 | 任务管理器里确认没有 QQ.exe 残留 |
| `E-UIA-004` | 找不到输入框 / 锚点 | 确认 QQ 停在某个会话的聊天界面 |
| `E-FG-001` | 抢前台失败 | 别用计划任务/服务起交互进程；先解锁屏幕 |
| `E-FG-004` | 切换会话后标题没变 | 先把窗口还原（别最小化） |
| `E-SEND-001` | 剪贴板写入失败 | 关掉剪贴板管理器/同步工具 |
| `E-SEND-002` | 发送按钮仍是禁用态 | 先跑「输入框写入测试」 |
| `E-SEND-003` | 输入框回读不符 | 自动化运行期间别手动编辑那个输入框 |
| `E-SEND-004` | 身份复核：标题不符 | 这是**防发错人**在起作用；先解决切会话 |
| `E-SEND-005` | 身份复核：QQ 号不符 | 最严重的一类，程序已拒发；跑一次「给所有会话取号」 |
| `E-SEND-007` | 该会话没有 QQ 号 | 跑一次「给所有会话取号」（降级为仅按昵称复核） |
| `E-LLM-001` | 没有 API Key | 「模型接入」里填一次 |
| `E-LLM-002` | 连不上模型接口 | 检查网络与接口地址 |
| `E-LLM-004` | 密钥无效（401/403） | 重新粘贴 Key |
| `E-LLM-005` | 接口地址或模型名不对（404） | 核对模型名与地址 |
| `E-LLM-006` | 被限流或额度用尽（429） | 调大「最小 LLM 间隔」；查服务商额度 |
| `E-CFG-001` | 配置文件语法错 | 报错里带行列号；或用「恢复默认值」重建 |
| `E-CFG-003` | 风控两项互相压制 | 两个数要同时放宽才有效 |
| `E-PROC-002` | 常驻运行中不允许执行该任务 | 先「停止常驻」 |

### 还不确定？用「诊断报告」

右上角 **诊断报告** → 跑 17 项检查 → **复制报告**。报告里：

- 先列**需要处理的项目**（带 `[X]` / `[!]`），每项给「现状」和「建议」
- 再列全部检查项
- 最后是环境明细（版本、路径、端口、进程数…）

把那段文本贴出来，就不用再回答「你的数据目录在哪」「QQ 是最小化的吗」这类问题了。

> 报告里的 `[X]` 才是要动手的，`[-]` 是「该项不适用」，`[!]` 是警告。

### 常见现象速查

| 现象 | 最可能的原因 | 怎么办 |
|---|---|---|
| 双击后什么都没发生 | 数据目录在只读位置，或端口被占 | 把 exe 移到可写目录；看 `logs\ui.log` |
| 托盘没有图标 | 图标创建失败 | 日志里有 WARN；用界面右上角「退出程序」退出 |
| ② 一直说找不到 QQ | 非标准安装路径 | 「运行环境」里手填 QQ.exe 完整路径 |
| ③ 体检失败，说"读不到界面" | QQ 没带无障碍参数 | 点「重启 QQ 到可读状态」 |
| 程序看起来卡住没输出 | 日志卡在缓冲里 | 子进程已强制无缓冲；仍异常就用 `build.bat console` 版本 |
| 改了参数没生效 | 常驻进程仍持有旧配置 | 保存后按提示重启常驻 |
| 日志被同一个错误刷满 | 持续性故障（如 QQ 被最小化） | 同一错误码 60 秒内只输出一次完整说明；看第一条的码 |

日志文件：`<数据目录>\logs\ui.log`。界面上可以「下载日志」。

## 9. 数据都在哪

```
<exe 所在目录>            ← 可写时用这里（便携模式）
├─ qq-agent.exe
├─ config.json            agent 的全部行为参数（可直接编辑，界面保存不会抹掉注释）
├─ secrets.local.json     API Key（不入库）
├─ app-settings.json      壳自己的设置（QQ 路径、端口、自启）
├─ state\                 会话上下文、QQ 号缓存、轮转指纹、心跳、停止哨兵
└─ logs\ui.log            运行日志
```

放 `C:\Program Files` 这类只读位置时，上面这些会自动落到
`%LOCALAPPDATA%\QQAgent\`（界面「路径信息」里能看到实际用的是哪个）。

## 10. 安全与合规（别跳过）

1. **这是「替你操作你这台电脑上已登录的 QQ」**，不碰协议、不碰群控、不碰任何账号凭据。
2. **只限个人自用、非商业、非群控**。历史上已有「QQ 自动抢红包」类工具被认定
   不正当竞争的判例（杭州法院）。一旦演变成对外提供服务或批量操作，性质就变了。
3. **不要在同一 IP/设备上同时跑自动化账号和日常主号**，尤其是放到服务器上的时候。
4. **CDP 端口（如果开了）等于宿主机上的任意代码执行入口**。默认只绑 `127.0.0.1`，
   需要远程访问就开 SSH 隧道，**绝不暴露公网**。
5. **前台守卫不要拆**。代码里的 `force_foreground` / `clear_editor` 自检是为了防止
   按键泄漏到你的其它窗口 —— 这是数据丢失级别的风险，不是代码风格问题。
