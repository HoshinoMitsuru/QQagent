### 五个坑（都写进 README 与对应函数的注释了）
1. **在宿主进程里碰 UIA 会把它弄坏**：一次失败的 `Invoke` → `COMError -2147220992`，
   之后每次 UIA 调用都 `-2147220991 事件无法调用任何订户`，**永不自愈**。
   同一张桌面、同一个 QQ，**换新进程读一切正常**。
   → 登录/探测一律派**一次性子进程**；宿主第一次碰 UIA 必须是 agent 那一次。
2. **登录完停在会话列表页**：`ml-list` / `ExEditor-qq-msg-editor` / `send-msg`
   只存在于聊天页（实测树里各 0 个），于是 `dom_exposed()` False 报 `E-QQ-004` ——
   按它去重启 QQ 是白折腾。→ 新增 `E-QQ-008`，判据是「`recent-contact-list` 在不在」。
3. **「点第一条会话」不够**：列表第一条是 `QQ游戏中心`（**公众号 webview**），
   点开有 `chat-header__contact-name` 但**没有聊天区**。
   → 用客观判据**迭代候选**：点一条 → 看 `ml-list` → 不在就换下一条。
4. **`GetWindowTextLengthW` 会挂死状态流**：读标题要**给窗口所属线程发消息**，
   对方不处理就无限期等。控制台 `/api/state` 每 2s 被轮询，于是整个状态流冻住，
   界面显示「心跳停更/连不上」。且在 `EnumWindows` 回调里发消息会**静默拿空**
   （实测 45 个窗口全空标题）。→ **两阶段**（先枚举不发消息，再读标题）
   + `SendMessageTimeoutW(SMTO_ABORTIFHUNG)` + 默认只读 QQ 类名窗口的标题。
5. **`_desktop_locked()` 在非活动桌面上必然为真**（那里本来就没有前台窗口）
   → 每次常驻启动都误报 `E-ENV-006 锁屏`。→ 判据改序：先问「输入桌面能不能打开」。

### 其他踩到的小坑
- `--args --once` 类问题再现：`--chat=mychat` 要写成 `=` 形式（值以 `-` 开头时会被当选项）。
- **venv 的 `python.exe` 在 Windows 上会再起一个子进程**，所以 `desktop.spawn` 返回的 pid
  ≠ 宿主自报的 pid。心跳里的 pid 才是真的（宿主写 `os.getpid()`）。
- 看门（心跳/停止）线程**必须在启动期就起来**，否则等 QQ/等登录那几十秒里界面显示
  「心跳停更」（误判卡死），按停止也没人接。
- 界面白屏级错误：**JS 字符串用双引号跨了行** → 已加 `node --check` + 元素 id / 图标名的
  引用完整性闸门（`test_ui.py §15`），因为后端接口测试全绿也照样白屏。
- `error_codes` 里 `rc` 字段名：宿主进程的返回码**不等于** agent 的返回码，
  启动期失败也走它 —— 原名 `agent_rc` 会把「启动就失败」读成「正常返回 0」。

## 追加：修「走隐藏桌面仍然报 E-FG-001 抢前台失败」

### 根因（不是偶发，是 100% 必失败）
- `E-FG-001` **只在剪贴板写入路径**里报（`agent.py` 的 `type_text`）。
- `uia.write_mode` **原先根本没在 `DEFAULT_CONFIG["uia"]` 里定义**，
  而 `type_text` 写的是 `(... .get("write_mode") or "clipboard")` → 缺省 clipboard。
- 剪贴板路径要求抢前台，而**独立桌面上 `SetForegroundWindow` 恒返 0** →
  隐藏桌面路线上每次发送都报 E-FG-001。
- 为什么源码树没暴露、exe 暴露：源码树的 `config.json` 是我 U1 时手动加过
  `write_mode: "wmchar"` 的；**`dist/config.json`（exe 首次运行生成的）没有这一项**。

### 修法：不再让人去手改配置，让程序自己认桌面
- `DEFAULT_CONFIG["uia"]["write_mode"] = "auto"`（三档：auto / wmchar / clipboard）。
- 新增 `_current_thread_desktop_name()` / `_input_desktop_name()` / `_independent_desktop()`：
  判据三条 —— ① 本线程桌面名 == 输入桌面名 → 不是独立桌面；
  ② 输入桌面打不开 → 也不是（那是锁屏/权限，我们仍在自己的桌面上）；
  ③ 输入桌面名是 `Winlogon` → 锁屏，仍不是。其余才是独立桌面。
- `QQWindow._route_write_mode()`：auto 按桌面选；**显式配了 clipboard 但处于独立桌面时
  也改用 wmchar**（那条路在那种桌面上不是「可能失败」而是「不可能成功」），
  并出一条 WARN 说明配置被环境覆盖（不静默改人的配置）。写错值 → 按 auto + WARN。
  选择结果只记一次，不刷屏。
- `uia.write_mode` 加进 `app/settings.py` 的 FIELDS（带三档下拉），界面上可改。
  ⚠️ 同时必须同步 `settings.py` 里那份 **agent.DEFAULTS 的副本** ——
  `test_ui.py` 有逐键比对闸门，漏了会报「缺失=['uia.write_mode']」。

### 顺带修的两处「会给出误导信息」

- `--input-test` 的第 4 步（清空输入框）原来直接 `force_foreground`：
  独立桌面上必然 False，打出来像失败。现在先试**免前台**的 `clear_editor_uia()`，
  不行且是独立桌面就如实写「跳过：没有前台窗口可借」，
  并额外打印**实际选中的写入路径**与 `独立桌面=` 便于排查。
- `E-FG-001` 的 fixes 补两条：独立桌面上不该出现本条；若出现说明
  `write_mode` 被显式设成了 clipboard。
