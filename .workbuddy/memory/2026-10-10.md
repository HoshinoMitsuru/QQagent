## 一、登录 bug：根因与修复（R4 + CU）

**根因（实锤，来自 `dist/state/host-grab.json` 现场）**：登录页真正的按钮类名是
`login-btn`，外层包着容器 `login-btn-wrap` —— **含 `login-btn` 这个子串**。
老代码 `_find_by(cls_has="login-btn")` 是「DFS 先访问父节点、命中即返回」，
于是永远拿到容器（`GroupControl`）：既无 `InvokePattern`，`DoDefaultAction`
也抛 `COMError(-2146233079)`。表现就是「程序不去按登录键」。
日志措辞还是「没看到登录按钮」，把真相盖掉了，排查方向直接跑偏。

**修法**（`app/hostagent.py`）：
- 新增 `_collect_by()`：命中后**继续往下**（wrap > btn 必须都能看见）。
- 新增 `_find_login_button()`：候选打分三级排序 —— 类名**按空格切 token 后精确等于
  `login-btn`** > 有 Legacy 且非 GroupControl > Invoke > Legacy；并把候选现场
  （类名/类型/矩形/Pattern）一路带进结果 JSON 供事后复盘。
- `login_state` / `do_login` 都改用 `_find_login_button`（判据与点击必须是同一个元素）。
- `do_login` 三条点击路依次兜底：`InvokePattern` → `DoDefaultAction` →
  **新增的窗口消息点击**；全失败时的 error 文案改成「找到「登录」按钮但三条点击路径
  都没走通：…」，与「没找到」分开（`hostd._ensure_login` 靠「没找到」四个字分流）。

**新增第三条点击路径**（`app/winmsg.py` 的 `click_at`）：WM_MOUSEMOVE / WM_LBUTTONDOWN /
WM_LBUTTONUP 投给 `Chrome_RenderWidgetHostHWND`（找不到才退回顶层并标注降级）。
不要求元素支持任何 Pattern —— 与「WM_CHAR 免前台」同源。

## 二、DPI 虚拟化（本轮真正的隐藏主角）

本机物理 2560x1600、系统缩放 150%（144 DPI）。进程 DPI-unaware 时 win32 坐标被
**虚拟化**成逻辑像素（窗口读到 `640x424`），而 **UIA 的 `BoundingRectangle` 永远是物理
像素**（同一窗口 `960x636`）—— 差 1.5 倍且各自内部自洽，谁也不会报错。

修法：`winmsg.enable_dpi_awareness()`，在 **hostagent / hostd 碰任何窗口之前**调用；
壳（tkinter/托盘）**不调**（调了界面会偏小）。成功判据**必须回读**
`GetProcessDpiAwareness` —— `SetProcessDpiAwareness` 失败时 ctypes 不抛异常，
只看返回值会谎报成功（第一版就写了这个假承诺，当场改掉）。

## 三、⚠️ 更正：一个我先前下错的判断

我先前把「抓图全黑」也算在 DPI 头上，**这是错的**。
- 真因：那台**残留 QQ 的渲染进程已经死了** —— `PrintWindow` 返回 0，图纯黑。
- 证据：同一台机器、同一张隐藏桌面上，一个**健康**的 QQ 抓图完全正常：
  `1471x991`、颜色 99 种、非黑占比 0.997、落盘 104 KB。
- DPI 真正修的是：**坐标一致性**（点击换算）与**抓图尺寸**（640x424 → 960x636）。

顺带补掉一个假承诺：`capture()` 原来对纯色图也报 `ok=True`。现在显式给 `blank`
（判据 `distinct_colors<=1`；**不能只看亮度** —— 纯红图亮度 76 但同样是单色），
`hostagent` 会写 `capture_note` 说明「这不是坐标问题」。

## 四、「连续对话常开」

`continuous.timeout_seconds = 0`（或负数）= **永不超时**。难点不在语义而在**落地**：
仓库既有惯例是 `or <缺省>` 兜底，而 0 是假值 → `... or 1800` 会把用户认真填的 0
悄悄改回 1800（配置看着生效、行为完全没变，不报错）。
修法：判据统一收进两个纯函数 `agent.cont_window()` / `agent.cont_expired()`，
所有取值点（`is_continuous` / `_cont_timeout` / `show_state` ×2 / 激活日志）改走它；
`app/settings.py` 的 `minimum` 30 → 0、hint 写明「填 0 = 常开」；`config.example.json`
与 README 同步。`dist/config.json` 已设为 0（备份 `config.backup-20261010-010525.json`）。
