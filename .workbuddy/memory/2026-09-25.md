### 五个坑（都写进 README 与对应函数的注释了）
1. **在宿主进程里碰 UIA 会把它弄坏**：一次失败的 `Invoke` → `COMError -2147220992`，
   之后每次 UIA 调用都 `-2147220991 事件无法调用任何订户`，**永不自愈**。
   同一张桌面、同一个 QQ，**换新进程读一切正常**。
   → 登录/探测一律派**一次性子进程**；宿主第一次碰 UIA 必须是 agent 那一次。
2. **登录完停在会话列表页**：`ml-list` / `ExEditor-qq-msg-editor` / `send-msg`
   只存在于聊天页（实测树里各 0 个），于是 `dom_exposed()` False 报 `E-QQ-004` ——
   按它去重启 QQ 是白折腾。→ 新增 `E-QQ-008`，判据是「`recent-contact-list` 在不在」。
3. **「点第一条会话」不够**：列表第一条是 `QQ游戏中心`（**公众号 webview**），
   点开有 `chat-header__contact-name` 但**没有聊天区**。
   → 用客观判据**迭代候选**：点一条 → 看 `ml-list` → 不在就换下一条。
4. **`GetWindowTextLengthW` 会挂死状态流**：读标题要**给窗口所属线程发消息**，
   对方不处理就无限期等。控制台 `/api/state` 每 2s 被轮询，于是整个状态流冻住，
   界面显示「心跳停更/连不上」。且在 `EnumWindows` 回调里发消息会**静默拿空**
   （实测 45 个窗口全空标题）。→ **两阶段**（先枚举不发消息，再读标题）
   + `SendMessageTimeoutW(SMTO_ABORTIFHUNG)` + 默认只读 QQ 类名窗口的标题。
5. **`_desktop_locked()` 在非活动桌面上必然为真**（那里本来就没有前台窗口）
   → 每次常驻启动都误报 `E-ENV-006 锁屏`。→ 判据改序：先问「输入桌面能不能打开」。

### 其他踩到的小坑
- `--args --once` 类问题再现：`--chat=mychat` 要写成 `=` 形式（值以 `-` 开头时会被当选项）。
- **venv 的 `python.exe` 在 Windows 上会再起一个子进程**，所以 `desktop.spawn` 返回的 pid
  ≠ 宿主自报的 pid。心跳里的 pid 才是真的（宿主写 `os.getpid()`）。
- 看门（心跳/停止）线程**必须在启动期就起来**，否则等 QQ/等登录那几十秒里界面显示
  「心跳停更」（误判卡死），按停止也没人接。
- 界面白屏级错误：**JS 字符串用双引号跨了行** → 已加 `node --check` + 元素 id / 图标名的
  引用完整性闸门（`test_ui.py §15`），因为后端接口测试全绿也照样白屏。
- `error_codes` 里 `rc` 字段名：宿主进程的返回码**不等于** agent 的返回码，
  启动期失败也走它 —— 原名 `agent_rc` 会把「启动就失败」读成「正常返回 0」。
