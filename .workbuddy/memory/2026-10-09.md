### 同步到 R4 的手法（更新：不是 `patch -p2 -l`）

- `git diff -- pc-agent-demo-vm` → `sed s#pc-agent-demo-vm/#pc-agent-demo-r4/#` → 先把 R4
  目标文件**整份 LF 化**再 `patch -p1`（逐字节确定匹配，不赌 `-l`/`--fuzz` 对 CR 的容忍度）
  → 打完还原 CRLF。

### 顺手抓到的一个**真回归**（不是我引入的，是 09-28 收拢时漏的）

`reset_to_defaults()` 把 `config.json` **整份换成内置默认值** → 密钥也被换掉了，
而界面文案承诺「API Key 不受影响」。收拢之前 key 住在 secrets 里，所以那句话当时是对的；
收拢之后它变成了**假承诺**：用户点一次「恢复默认」就得重新粘一遍 Key。

- 修法：先把盘上现有的 `llm.api_key` 捞出来（掩码则丢弃），写回模板再落盘；
  返回值加 `kept_api_key` 供界面/测试对账。
- **同时踩到一个陷阱**：`agent_defaults()` 返回的是**模块级 `_LOCAL_DEFAULTS` 本体**，
  老代码 `template = dict(agent_defaults())` 只是**浅拷贝** —— 只要在 template 上做
  `_set_path`，就会把用户的密钥写进那份全局默认值（下一个新装用户直接带着别人的 Key）。
  所以必须 `copy.deepcopy`。测试里加了一条断言专门盯这件事
  （`SET.agent_defaults()["llm"]["api_key"] == ""`）。

## 收尾四：QQ 号出库（代码与注释一律不硬编码）

用户指令原文：
> 代码工程内肯定不能硬编码 QQ 号，注释里也要脱敏，QQ 号也要作为敏感信息存在本地。

### 为什么必须做

昵称是"名片"，QQ 号是"身份证"：纯数字、可被反查、且**不受昵称改名影响**。
收尾三只把昵称/备注名换掉了，QQ 号仍是真实值，且因为不在词表里，**闸拦不住**——
一旦提交进去，就是一条永久可追溯的关联。所以这次把它当一等敏感信息处理。

### 做法

- 词表（`tools/sensitive-words.local.txt`）**先**加 6 个整号 → 跑 `--all` 拿到"替换前"基线
  （82 处命中）→ 替换 → 再跑 `--all` 拿到 0 命中。先立哨兵再动手，才证明得了"一个都不剩"。
- 只登记**整号**，不登记数字碎片：文字类的碎片（如 `测试目标A` 拆成两半）能拦"只写一半"，
  数字碎片（`3302676`）则会在无关编号上误报，得不偿失。
- 替换工具仍是 `.workbuddy/tmp/sanitize_20261009.py`，`--real` 从命令行传、逐文件报行尾前后一致。

### 规模

**37 个文件 / 82 行 / 86 处**（6 个号码），行尾全部保持原样（工具逐个文件报 CRLF/LF 一致）。
按号分：主联系人 53、群聊卡片示例 13、测试群 8、小清澈自身 8、`凡杜林办事处` 3、`小清澈教研室` 1。

### 假号段约定

`100000001`…`100000006`，与真实号**一一对应、不许复用**（对照表里有映射）。
选它的理由：`1` 打头的 9 位在任何语境下都读得出"这是示例"，且落在
`qqid.py` 的 `RE_UID_TEXT` 允许区间（`\d{5,12}`）内，不会把文档里的快照例子写坏。

### 两个判断

1. **`private:100000001` 这种会话键也一起换**：它是"昵称 → 会话键"映射机制的核心例子，
   换掉不影响语义（键的形状才是重点，具体号不是）。
2. **`sealdiceextension/*.js` 的 `const claritasQq` 也一起换**（7 个文件 + 1 处测试夹具）：
   它虽被注释成"请根据实际情况修改"，但**默认值本身**就是硬编码的真实号 ——
   一个模板级默认值不该是维护者本人的 QQ 号。`test/teach-smoke-test.js` 的
   `[CQ:at,qq=...]` 夹具同步改成同一个假号，保证"@自己"这条分支的语义不变。
