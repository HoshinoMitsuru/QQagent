# 小清澈 · AI 聊天工作区

**作者**：bilibili@嗅尘紫蝶 　**许可证**：木兰宽松许可证，第 2 版（`LICENSE`）

这个仓库里同时装着三条线的工作，它们共享同一个「小清澈」的设定与人格，但形态不同：

| 线 | 是什么 | 跑在哪 | 当前状态 |
|---|---|---|---|
| **① 小清澈 JS 插件** | 海豹骰子（SealDice）插件，群聊/私聊里的 AI 陪伴 | 海豹骰子 | `小清澈3.0.js`（v3.0.0），可用 |
| **② PC 端 QQ AI 代理** | 不碰协议，直接操作本机 QQ 客户端窗口来做 AI 回复 | Windows | 两棵并列目录树，见下 |
| **③ 冒烟测试** | 插件的 Node 冒烟脚本 | Node | `test/`，可用 |

## ① 小清澈 JS 插件（海豹骰子）

**当前版本：`小清澈3.0.js` —— v3.0.0，`EXT_NAME = "AiChat"`**

直连 DeepSeek / OpenAI 兼容接口，**不依赖任何本地服务器**。

### 能力

- **`.ai` 指令**：`reset` / `stop` / `list` / `on` / `off` / `teach` 系列
- **自动唤起**：中文前缀触发词（默认 `小清澈，`，注意是中文逗号）
- **连续对话模式**：活跃期内免触发词，默认 30 分钟超时
- **多人格切换**：仅预设人格（自定义人格是服务器版专属能力）
- **图片识别**：视觉 API 直连，群聊下走**图片白名单**（须由本轮触发过的用户发出）
- **URL 网页读取**
- **用户主动调教上下文**：以「小清澈：」开头的消息以 `assistant` 角色写入历史
  —— 见 [`小清澈3.0-调教机制说明.md`](小清澈3.0-调教机制说明.md)
- **沉浸式陪伴**：私聊恒免触发词、且不拼接 `@昵称` 前缀；群聊默认需触发词

### 版本谱系

按 `EXT_NAME` 分成三代，**同名版本彼此互斥**（插件加载时会 `seal.ext.find` 提前返回）：

| 文件 | 版本 | EXT_NAME | 说明 |
|---|---|---|---|
| `小清澈3.0.js` | 3.0.0 | `AiChat` | **当前版**。在 2.3 基础上加「用户主动调教上下文」 |
| `小清澈2.3.js` | 2.3.0 | `AiChat` | 合并直连版的 4 项功能修复（fetch 超时保护等） |
| `小清澈2.2.js` | 2.2.0 | `AiChat` | 人格提示词 / 对话文案主分支 |
| `小清澈2.0.js` | 2.0.0 | `Mitsuru-AiChat-Companion` | **QQ 陪伴特化版**（识图与对话默认全开，可与 1.7 共存） |
| `小清澈1.7.js` / `小清澈.js` | 1.7.0 | `Mitsuru-AiChat` | 通用版，图片识别需手动开启 |
| `小清澈1.3 ~ 1.6.js` | 1.3–1.6 | `Mitsuru-AiChat` | 历史版本，留档 |

> `小清澈.js` 与 `小清澈1.7.js` 内容相同，前者是「不带版本号的当前副本」。

### 使用

安装：把目标 `.js` 放进海豹骰子的插件目录，重载插件即可。配置项内置且已封好，可直接用。

| 指令 | 作用 |
|---|---|
| `小清澈，<内容>` | 唤起（中文逗号） |
| `.ai reset` | 清空当前会话历史 |
| `.ai stop` | 退出连续对话模式 |
| `.ai list` | 查看可用人格列表 |
| `.ai on` / `.ai off` | 群聊切换「免触发词 / 需触发词」（私聊不受影响） |
| `.ai teach` / `.ai teach undo` / `.ai teach clear` | 查看 / 撤销 / 清空最近的调教记录 |

详细机制、识别规则与权限见 [`小清澈3.0-调教机制说明.md`](小清澈3.0-调教机制说明.md)。

### 冒烟测试

```bash
node --check 小清澈3.0.js
node test/teach-smoke-test.js        # 调教机制专项（32 项）
node test/plugin-smoke-test.js       # 插件整体（含图片白名单场景）
```

## ② PC 端 QQ AI 代理（两条路线）

目标：用「操作本机 QQ 客户端」代替协议接入，绕开 QQ 协议风控。
不碰协议、不碰硬件模拟，程序做的只是**读控件、写文字、触发发送按钮**。

这条线**并行维护两棵独立的目录树**，因为它们的运行前提完全不同：

| | **V1 · 附着式** | **V2 · 独立桌面托管** |
|---|---|---|
| 目录 | [`pc-agent-demo-vm/`](pc-agent-demo-vm/) | [`pc-agent-demo-r4/`](pc-agent-demo-r4/) |
| 运行前提 | 附着到**已经登录好的那个桌面**上的 QQ | 自己建一张**用户看不见的桌面**，把 QQ 启动上去 |
| 写文本怎么走 | 抢前台 → 剪贴板 → 按键 → 归还前台 | 一次窗口消息（那张桌面上没有前台可抢） |
| 打扰用户吗 | 会：写入期间 QQ 被置顶、键盘输入被接管 | 不会：QQ 不在用户的桌面上，屏幕上什么都没有 |
| 适用场景 | **虚拟机 / 专用机** | **用户自己的机器** |
| 交付 | `dist\qq-agent.exe`（含 `-noadmin` / `-console` 变体） | 同上，`build.bat` 一次构建，`test_exe.py` 52 项验收 |
| 状态 | 可用，已实机验证（git tag `v1.0-vm-attach`） | 机制层 + 常驻 + 控制台面板 + 打包均已实机验证（tag `v2.0-r4-mechanism`） |

**为什么不是二选一**：V2 解决的是 V1 最大的软肋（唯一会打扰用户的一步），
但它换来一个新的硬前提 —— 隐藏桌面上的 QQ 没人能手动操作，
所以「登录」「打开会话」这些原本由用户顺手完成的事必须由程序自己做。
两条路各有代价，都留着。
