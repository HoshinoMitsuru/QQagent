## 2. 【必做】验证「我方/对方」方向判定

**这是现在唯一没验证的核心逻辑。** 之前只验证了「对方」那一半，
因为当时的群聊视窗里没有你自己发的消息。

### 执行

1. 在 QQ 里打开一个**私聊**会话
   （建议用你自己的小号，或「我的电脑 / 文件传输助手」这类不会打扰别人的会话）
2. **在 QQ 里手动发一条消息**，比如：
   ```
   测试：这是我自己发的
   ```
3. 回到 PowerShell，执行：

```powershell
python -X utf8 agent.py --peek 10
```

### 预期输出

```
========================================================================
只读诊断：附着 QQ 并解析最近消息（不发送任何内容）
========================================================================

[窗口] title='你的私聊对象名'  群聊=False  群人数=0
[账号] 自动识别的自己昵称='Claritas-小清澈'
[锚点] 消息列表=OK  输入框=OK  发送按钮=OK  发送按钮禁用=True

共解析 10 条（文档顺序 = 时间顺序）：

  【对方】对方昵称  key=aid:7684140143090032906
        xxxxxx
  【我方】Claritas-小清澈  key=aid:7684140143090032912      ← 你刚发的那条
        测试：这是我自己发的

核对要点：
  1) 「我方/对方」是否与 QQ 界面上气泡的左右位置一致
  2) 昵称对不对、正文有没有漏字多字（尤其带 @ 的消息）
  3) 最后一条是否就是 QQ 里最新那条
```

### 逐项核对

| 检查项 | 要看到 | 不符合怎么办 |
| --- | --- | --- |
| 会话类型 | `群聊=False` | 私聊却显示 `True` → 判定有 bug，把输出发我 |
| 自己昵称 | `Claritas-小清澈` | 显示为空或不对 → 在 `config.json` 的 `chat.self_nickname` 手填 |
| 方向 | 你刚发的那条是 `【我方】` | 全标成 `【对方】` → 把这 10 行输出发我 |
| 正文 | 和你发的一致 | 有缺字多字 → 把那几条发我 |

> **这一步的结论直接决定后面能不能跑。** 如果方向判定反了，
> 程序会把自己的消息当成对方消息，然后自己跟自己聊起来。

## 3. 【可选，但建议做一次】验证真的能发出去

这一步**会真的产生一条消息**，所以我没替你跑。
请选一个不会打扰别人的私聊会话。

### 执行

```powershell
python -X utf8 agent.py --send "这是一条自动发送测试，忽略即可"
```

### 预期

| 场景 | 预期结果 |
| --- | --- |
| 当前是群聊 | 直接拒绝：`[X] 当前会话是群聊，已拒绝发送。` |
| 当前是私聊 | QQ 窗口被提到前台 → 输入框出现文字 → 自动发出 → 回读最近 3 条 |
| 回读结果 | 你刚发的那条应显示为 `【我方】` |

**安全阀**：`--send` 默认拒绝在群聊里发送，只有显式加 `--force` 才会在群里发。

> 已经验证过的部分（用「粘进去再清空、不按发送」的方式测的）：
> 剪贴板写入正确、输入框精确定位到 ProseMirror、粘贴成功、
> 发送按钮禁用状态从 `True` 翻成 `False`。
> **只剩最后「点发送按钮」这一下没验证。**

## 4. 跑常驻循环（真正的 demo）

### 4.1 先只读观察 2~3 分钟

```powershell
python -X utf8 agent.py --dry-run
```

### 预期日志

```
[13:20:01] INFO  已附着 QQ 窗口，标题='xxx'，群聊=False
[13:20:02] INFO  基线建立完成，忽略已有 10 条历史消息
[13:20:02] INFO  进入循环（poll=0.8s，always_reply=True）
[13:20:35] RECV  对方昵称: 你在吗
[13:20:35] DRY   dry-run：只记录，不调用模型
[13:21:10] SKIP  群聊『某某群』已跳过
[13:21:22] SKIP  非文本消息已跳过（[图片]）
```

要确认的行为：
- 有对方向你发消息时出现 `RECV`（**不会**出现 `SEND`，因为是 dry-run）
- 群聊消息被 `SKIP`
- 图片等被 `SKIP 非文本消息已跳过`
- 自己发的消息**不**触发 `RECV`

确认无误后 `Ctrl+C` 退出。

### 4.2 正式运行

```powershell
python -X utf8 agent.py
```

它会真的调用模型并替你在私聊里回复。

## 5. 运行期间的注意事项

| 事项 | 说明 |
| --- | --- |
| **不要操作那个 QQ 窗口** | 程序靠模拟按键发消息，你一插手就互相干扰 |
| **窗口不能最小化** | 最小化会让无障碍树失效，读不到消息 |
| 被别的窗口挡住 | 没关系，只有「最小化 / 缩托盘」才不行 |
| 发送时 QQ 会跳到前台 | 模拟按键的固有限制，挡不住 |
| **剪贴板会被覆盖** | 发送靠剪贴板粘贴，你复制的内容会被替换 |
| 切换会话 | 标题变化后约 5 秒内自动重扫 |
| 退出 | `Ctrl+C` |
| 关掉 PowerShell 窗口 | 程序随之结束 |


## 7. 调参（改 `config.json`）

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `chat.self_nickname` | `""` | 留空则自动识别；识别不准时手填 |
| `chat.private_chat_only` | `true` | 只做私聊，群聊一律跳过 |
| `chat.always_reply` | `true` | 改 `false` → 变成触发词模式 |
| `chat.trigger_prefixes` | `["小清澈","清澈"]` | `always_reply=false` 时的触发词 |
| `chat.reply_cooldown_seconds` | `1.5` | 两次回复的最小间隔 |
| `chat.poll_interval_seconds` | `0.8` | 轮询间隔 |
| `llm.system_prompt` | 小清澈人格 | **改人格就改这里** |
| `llm.api_base` / `llm.model` | DeepSeek | 换模型 |
| `llm.api_key_file` | 指向 `secrets.json` | 密钥来源，已跑通 |
| `teach.names` | `["小清澈","Claritas-小清澈"]` | 调教前缀名 |
| `teach.enabled` | `true` | 调教开关 |

**调教机制**：对方发 `小清澈：你想让我说的话` → **不触发模型调用**，
直接以 `assistant` 角色写入上下文，等于替 AI 说话，下次对话会延续。

## 8. 出问题时的对照表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `找不到**可见**的 QQ 主窗口` | QQ 缩在托盘 | 双击托盘图标，把主窗口打开 |
| `[锚点] 消息列表=缺失` | 没点进任何会话 / 没带无障碍开关 | 点进一个会话；确认启动参数 |
| 读到的条目全是空 | 窗口被最小化 | 恢复窗口，不要最小化 |
| `找不到 QQ 输入框` | 同上 | 同上 |
| 发送按钮一直禁用 | 文本没粘进输入框 | 看剪贴板是否被别的程序占用 |
| 自己的消息也标成 `【对方】` | 昵称没识别对 | `config.json` 里手填 `self_nickname` |
| QQ 升级后读不到 | 控件结构变了 | 跑 `probe.py --depth 30 --dump`，把 `probe-stdout.txt` 发我 |
| 程序乱回历史消息 | 基线建立前就有新消息涌入 | 重启程序（启动时会忽略已有消息） |
